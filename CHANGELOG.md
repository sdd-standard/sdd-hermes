# Changelog

All notable changes to `sdd-hermes` will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## [2.1.0] - 2026-11-15

### Added
- **Initial official release for Hermes Agent (`NousResearch/hermes-agent`)** aligned with **Pure SDD Standard v2.1**:
  - `plugin.yaml` & `__init__.py` (`register(ctx)`) wiring 8 skills, 8 slash commands, 2 passive mechanical tools (`sdd_check_ids`, `sdd_say_do_audit`), and 4 lifecycle hooks (`on_session_start`, `pre_llm_call`, `pre_tool_call`, `post_tool_call`).
  - **8 Canonical Skills**: `sdd-init`, `sdd-adopt`, `sdd-specify`, `sdd-design`, `sdd-tasks`, `sdd-implement`, `sdd-change`, `sdd-validate`.
  - **4 Subagent Profiles (`agents/`)**: `sdd-architect` (`deep`), `sdd-implementer` (`balanced`), `sdd-validator` (`balanced`, 100% passive read-only), `sdd-doc-writer` (`fast`).
  - **Native Python Mechanical ID Guard (`scripts/check_ids.py`)**: Zero-config, grammar-based (`PREFIX[-SCOPE][-Mn]-NUMBER`), exclusion-scoped ID verifier running on Python 3 standard library without requiring Node.js (alongside `scripts/check-ids.mjs` for Node/CI compatibility).
  - **Passive Layer-0 Say-Do Gate (`scripts/say_do_gate.py` — `DÍVIDA-SDD-01`)**: Passively tracks session terminal commands and file writes via `post_tool_call` to mechanically verify that tests/builds ran with `exit_code == 0` after the latest code edit.
  - **Pre-Design `Validate-Gap` Check (`DÍVIDA-SDD-02`)**: Integrated into `sdd-design` and `sdd-change` for brownfield domain comparison before creating `DES-xxx` decisions.
  - **3-Layer 100% Passive Quality Gate (`DÍVIDA-SDD-03`)**: Unified milestone gate combining Layer 0 mechanical checks with a two-stage passive `sdd-validator` report (`Stage 1: Strict GEARS & Scope Compliance` → `Stage 2: Constitution, Security & Global Infra Quality`).
  - **Learning Loop Governance Guard (`DÍVIDA-SDD-04`)**: `pre_tool_call` protection preventing autonomous self-learning loops from silently mutating `constitution.md` or canonical SDD skills.
  - **Scoped Low-Friction Interview & Proactive Scope Slicing (`DÍVIDA-SDD-05`)**: `sdd-architect`, `sdd-specify`, and `sdd-change` restrict code reading strictly to the touched domain, ask at most 3–5 focused questions with recommended defaults, and proactively propose splitting or narrowing oversized changes.
  - **Elastic Pagination with Auto-Compaction (`-02.md` — `DÍVIDA-SDD-06`)**: Enforces the 150-line file cap + 4–5 line paragraph density limit while supporting `10-validation-02.md` and `11-project-memory-02.md` overflow shards that are automatically linked in the main header and deleted once debts/active fronts are resolved.
  - **Deterministic Severity Taxonomy & Domain Calibration (`DÍVIDA-SDD-07`)**: Embeds the Universal SDD Severity Matrix (`Critical | High | Medium | Low`) inline in `rules/sdd-core-rules.md`, `HERMES.md.template`, `agents/sdd-validator.md`, and `templates/specs/10-validation.md`, paired with project-specific risk calibration in `templates/constitution.md.template`.
  - Full canonical template suite (`HERMES.md.template`, `constitution.md.template`, `specs/00..11` including `11-project-memory.md`, `changes/`, `archive/`).

### Fixed (post-release audit)
- **Say-Do Gate approved failing tests (`DÍVIDA-SDD-01`)**: `_extract_exit_code` defaulted to `0` and did not parse the JSON string Hermes passes as `result`, so a failing test run was reported as `VERIFIED_PASS`. The result is now parsed as JSON and an undetermined exit code is `None`, which never counts as proof.
- **Say-Do Gate passed vacuously**: the audit tool read the `"default"` session while the hook recorded under the real `session_id`. The tool now audits the active session, accepts `all_sessions` (code edited by a `delegate_task` subagent), and returns `NO_EVIDENCE` (not a pass) on an empty ledger. Test detection requires the runner to head a command segment and rejects masked runs (`|| true`, pipes without `pipefail`, dry-run flags); file edits made through the terminal (`sed -i`, redirects, `git apply`…) invalidate earlier proof; the latest run of each command is the one that counts.
- **Hook and tool contracts**: `pre_llm_call` now injects memory by returning `{"context": ...}` (Hermes ignores the return value of `on_session_start`, which previously also marked the session as injected, so memory was never injected); `pre_tool_call` now returns `{"action": "approve" | "block", "message": ...}` instead of the Claude Code `decision` shape Hermes ignores; tool handlers accept `**kwargs` and return JSON strings.
- **Learning-loop guard (`DÍVIDA-SDD-04`)**: now covers `docs/sdd/constitution.md` (human approval gate) and matches plugin files by resolved path under the plugin root instead of the substrings `sdd-hermes`/`sdd-workflow`; also covers `skill_manage` on canonical skills and writes made through the terminal, while reading or copying templates from the plugin stays allowed.
- **`check-ids` vs. templates**: `templates/specs/08-acceptance.md` declared `AC-001 (FR-001)`, a format the ID guard never recognised as a declaration, and `09-traceability.md` cited concrete IDs; a freshly initialised project failed Layer 0 with 3 orphans. The AC ID now stands alone with a `Requirement:` field and the matrix row uses placeholders. `check_ids.py` no longer silently skips non-UTF-8 files (parity with `check-ids.mjs`).
- **Layer 0 short-circuit**: `sdd-validate`, `sdd-change` (archive) and the `sdd-validator` prompt no longer run Stages 1–2 over a failing mechanical floor; the validator invokes the two passive tools itself instead of trusting a relayed summary.
- **`session_start.py`**: accepts both the canonical ledger format and the Markdown variant (`### TASK-001` / `- **Status:**`), no longer lists the ledger legend as a task, and warns when `11-project-memory.md` or `10-validation.md` exceed 150 lines.
- **Constitution interview** (`sdd-init`, `sdd-adopt`) now asks for the domain criticality calibration (section 6).
- Slash-command handlers now state the plugin root so `templates/...` paths resolve; dated amendment notes require explicit **user** approval; baseline immutability wording fixed from `00–10` to `00–06`, `08`, `09` (volatile `07`, `10`, `11` exempt); `sdd-change` headings relabelled to the 3 canonical states; `guard-install` extended (`poetry add`, `go get`, `composer require`, `gem install`); `.gitignore` now ignores Python bytecode.
- **Maturity lifecycle enforced (`Draft → Reviewed → Approved`)**: only the user promotes an artifact (batch approval allowed); consuming a `Reviewed` artifact that is not yet `Approved` records a maturity debt (`Type: Maturity`) with a snapshot of the consumed IDs and clause text, closed unchanged or after revalidating the dependents; item-level `Auto-Approved` allowed only for items that do not touch constitution sections 4 and 6, derive 1:1 from a user-approved item (or apply a written convention) and carry a `Motivo:` line. Specify, design, tasks and change skills, the rules and the `sdd-validator` checklist were updated (`Auto-Approved` outside the criteria is `High`).
- **User Risk Acceptance formalized**: a `Critical`/`High` debt stops blocking only with a user acceptance recorded in the `VAL` (who, date, rationale, review trigger); the severity is kept, Layer 0 failures cannot be accepted, and accepting a constitution violation requires an entry in the new constitution section 8 (*Exceções vigentes*). The `implement` entry gate now blocks only `Critical`/`High` debts **without** acceptance (it used to block accepted debts too).
- **Elastic pagination without a paragraph cap**: the unverifiable "4–5 lines per paragraph" limit was removed. The pagination trigger is now 150 lines **or** characters: 16,000 for `10-validation.md` and 7,000 for `11-project-memory.md`. The memory ceiling comes from the platform's injection budget (Hermes caps hook-returned context at 10,000 characters by default and replaces the rest with a head/tail preview and a file path) minus ~3,000 characters reserved for alerts, active tasks and active changes. The session hook never relies on the platform cut: it injects by priority and, when the memory does not fit, injects only *Estado Atual*, *Próximos Passos* and *Pendências* with an explicit instruction to read the whole file. Documented in the README, the hook header and the `11-project-memory.md` template. The `10-validation.md` template defines the mandatory debt content (`Issue`, `Evidence`, `Impact`, `Recommendation`, `Closure Criteria`, `History`, plus `Type`, `Links`/`Parent`, `Risk Acceptance`), debt fragmentation and a short greppable `Status`; session hooks warn on either threshold.
- **Session hooks list active changes** (`docs/sdd/changes/<name>/`), one line each with the count of unfinished and `In Progress` tasks, flagging changes with no active task (archive likely pending).
- **Constitution template**: section numbering 1–8 declared canonical (skills and validators cite "section 6" and "section 8"); new section 8 *Exceções vigentes*; section 3 asks for the official Say-Do test command in every plugin.
- **Rules loaded from the plugin, not duplicated in `.hermes.md`**: `rules/sdd-core-rules.md` (rewritten to fit the platform limits) is registered as two system-prompt sections (`ctx.register_system_prompt_section`, < 4,000 characters each) with the plugin root resolved at runtime; `.hermes.md` now carries only project-specific context. On Hermes builds without that API, the rules are injected on the first turn by a dedicated `pre_llm_call` callback.
- **`sdd-validator` read-only enforced by the plugin**: a subagent delegated with `goal` starting with `[sdd-validator]` is tracked through `subagent_start`/`subagent_stop`; `pre_tool_call` blocks write, patch, skill, delegation and code-execution tools for it and only allows read-only terminal commands (fail-closed allow-list). The previous `tools_mode: read_only` front-matter was never read by any code. Skills and rules describe the delegation protocol (`goal` marker + profile file as `context`).
- **`plugin.yaml` aligned with the manifest v2 schema**: added `manifest_version: 2` and `api_version: 1`, `repository` replaced by `homepage`, removed `provides_commands` (commands and skills are registered in code), kept `requires_hermes`, and declared the new `subagent_start`/`subagent_stop` hooks.
